# 团队共享数据（本机落盘，不入库）

这个目录放**需要跨机器看同一份**的运行时 JSON，由代理
（`publish/proxy.js` 的 `/local/*` 端点）读写，前端不直接碰文件。

## 当前文件

| 文件 | 用途 | 对应端点 |
| --- | --- | --- |
| `saved-queries.json` | 首页「常用查询」的团队库 | `GET/POST /local/saved-queries` |
| `saved-queries.example.json` | 空模板（入库，用来占位目录结构） | — |

`saved-queries.json` **不入库**（含真实查询条件 / 人名 / 部门，见根 `.gitignore`），
首次写入时代理会自动创建，缺失就是「还没有人存过」。

## 怎么才算「同一个团队库」

**同一个文件路径就是同一个库。** 三种用法：

1. **只在本机用**：什么都不用配，默认就是这里的 `shared/saved-queries.json`。
2. **同一个 git 工作区多人用**：直接在这里读写，但文件不入库，
   各自看到的还是各自的磁盘 —— **这只解决「路径统一」，不解决同步**。
3. **跨机器真正共享**（推荐）：在根目录 `.env` 里把路径指到一个所有人都能访问的位置：

   ```env
   # Windows 网络盘（注意反斜杠要写两个）
   PROXY_QUERIES_FILE=\\\\nas\\share\\saved-queries.json
   # macOS / Linux 挂载点或同步盘
   PROXY_QUERIES_FILE=/Users/Shared/spider/saved-queries.json
   ```

   设了之后代理就读写那个文件，**所有人看到的是同一份**，
   同时本机旧的那份会自然停更（不再被读写，留着当备份即可）。

## 合并规则（多人同时写不会互相覆盖）

代理收到 POST 时是**先读再合并再落盘**，不是直接覆盖：

- 「同页面 + 同名」视为同一条；
- `hits / saves / lastAt` 取 max —— 反复同步不会把热度刷上去；
- 删除走**墓碑**（`deleted` 数组，保留 30 天），否则同事的本地副本一推送就把删掉的记录「复活」。

## 并发

只有「后写者 + 合并」，**没有文件锁**：两人同一瞬间点击，可能有一方的 hits 少算 1
（记录不会丢）。真高并发再说。
