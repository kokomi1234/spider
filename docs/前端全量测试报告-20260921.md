## 三、发现的问题（按严重程度）

### P1-1 ｜ 首页「导 出」抛未捕获异常 `ReferenceError: items is not defined`【高】

- **关联文件**：`publish/js/page/home.js:731`（函数 `exportQueries()`）
- **现象**：点击首页「导 出」后，文件其实已经下载成功（`常用查询_2026-09-21-01-35-45.json`），
  但随后第 731 行 `showToast(\`已导出 ${items.length} 条…\`)` 引用了**从未定义**的 `items`，
  抛出未捕获 `ReferenceError`，被 bootstrap 全局兜底捕获。
  用户感知：**导出后没有任何成功提示**，控制台报错。
- **复现步骤**：
  1. 打开 `http://127.0.0.1:3055/home`
  2. 点右上角「导 出」
  3. 观察：文件下载成功，但页面无 toast；控制台出现 `[bootstrap] 未捕获Promise 拒绝：items is not defined`
- **稳定复现**：是（两轮独立测试均命中）
- **根因**：2026-09-20 架构改版把导出主体改成**服务端团队库**后（`exportJsonAsync()`），
  函数里已经不再有本机 `items` 数组，但 toast 那行没跟着改。
- **修复建议**：`exportJsonAsync()` 的返回值是 JSON 文本，条数应从它解析出来，
  或让 `SavedQuery` 提供 `exportJsonAsync()` 的 `{text, count}` 形态。
  最小改法：`const n = (JSON.parse(text).items || []).length;` 再进 toast。
  ⚠️ 注意：解析前要判 `text` 合法性，别在导出路径上再引入第二个异常。

### P2-1 ｜ 401 无「Token 过期」引导【中】

- **关联文件**：`publish/js/core/api-client.js:188-192`（协议层统一抛 `HTTP 401 …`）、
  `publish/js/core/publish-response.js:47-49`（仅此处识别 401）、`publish/js/ui/token-manager.js`
- **现象**：注入 401 后，页面只显示「⚠️ 查询失败：认证失败」。
  后端 token 约 12 小时过期，过期后**用户不知道该去点「🔑 Token」**。
  三个查询页 + 首页都有 Token 入口，但没有任何自动提示或跳转。
- **复现步骤**：拦截接口返回 `401 {code:401,msg:'认证失败'}` → 点查询 → 只见泛化失败文案
- **修复建议**：在 `api-client` 或 `query-feedback` 加一层 401 识别，
  toast 文案追加「请点右上角 🔑 Token 更新」，或直接打开 Token 弹窗。
  按 `memory.md` §1「不写提示文字」的口径，这条属于**操作失败必须说原因**的例外，应当保留。

### P2-2 ｜ 订阅页三个多选下拉选项为空，且无任何加载失败提示【中】

- **关联文件**：`publish/js/page/subscription.js:668-671`（`loadProviderServeNos()` 不判 `res.ok`）、
  `subscription.js:645-655`（`loadCallerServeNos()` 仅 `console.warn`）
- **现象**：展开「高级筛选」，点「提供方服务编号 / 接口编码 / 提供方系统服务编号」
  任一多选，面板只显示「没有匹配项 全 选 清 空 确 认」，
  **既不提示加载失败，也不提示"正在加载"**。用户无法区分"业务上没数据"和"接口挂了"。
- **复现步骤**：
  1. 打开 `/subscription` → 点「▼」展开高级筛选
  2. 点任一 `.msel` 输入框 → 面板显示「没有匹配项」
- **修复建议**：`loadProviderServeNos` 补 `res.ok` 判断；失败时给该多选加一个
  「选项加载失败」的行内标记（`table-utils.EMPTY_TEXT` 那套口径），不要伪装成空态。

### P2-3 ｜ 已订阅面板「📄 选择文件」未拉起文件选择器【中】

- **关联文件**：`publish/js/ui/subscribe-ui.js:264-318`（`showImportForm`）
- **现象**：发布页 → 点「已订阅 (N)」→ 「📥 批量导入」→ 弹窗里有文本域和
  `<input type="file" accept=".txt,.csv,.text">`，但点击「📄 选择文件」**没有拉起文件选择器**（Playwright 监听 `filechooser` 事件 5s 未触发）。
  文本域粘贴路径正常（已验证导入 2 条成功）。
- **复现步骤**：`/publish` → 「已订阅」→ 「📥 批量导入」→ 点「📄 选择文件」
- **修复建议**：确认该按钮是否绑定了 `input.click()`；另外 `accept` 里的 `.text` 不是标准扩展名，建议改成 `.txt,.csv`。
  同时按 §6 的静态审查结论，`readAsText` 未指定编码（国内 CSV 多为 GBK），建议显式 `'utf-8'` 或做编码探测。

  或补一条 `@media (max-width:600px)` 覆盖。按 `AGENTS.md` §6.7，只走 `theme.css` 令牌，别写内联。
