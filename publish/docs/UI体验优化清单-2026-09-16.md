## 一、布局与对齐类（与分页栏同类的问题）

### A1 ★★★ 首页结果表有 4 列表头没跟着内容居中
- **位置**：`publish/index.html:156-165`（居中规则只写了 `.cell-status/.cell-check/.cell-sub/.col-op`）、`:501-510`（10 个 `<th>` 全都没有 class）、`publish/theme.css:841-850`（`thead th { text-align: left }`）
- **现状**：`[实测]` 10 个表头 **全部 `text-align: left`、class 全为空**；而对应数据格是居中的（`服务状态 / 是否已核对 / 订阅标记 / 操作`）。
- **问题**：表头左对齐、内容居中，徽章与操作按钮相对标题整体偏右；横向滚动时错位更明显。订阅页与 task 页表头/内容都是左对齐，是自洽的 —— **只有首页这一处冲突**。
- **建议**：给这 4 个 `<th>` 补 `col-status/col-check/col-sub/col-op` 类，并在页面样式里加 `.result-table thead th.col-* { text-align: center }`；顺带把 `#` 列一起居中。
- **成本**：小

### A2 ★★★ 文档选择弹窗的分页栏被下拉撑塌（804px 的"每页条数"）
- **位置**：`publish/index.html:815-828`（`.doc-pager` 结构）、`publish/theme.css:1556-1565`（`flex-wrap: nowrap`、无 `justify-content`、子项无宽度约束）、`:350`（`.searchable-select { width: 100% }`）、`js/ui/doc-picker.js:166-170`（`docPageSize` 被包成可搜索下拉）
- **现状**：`[实测]` 原生 `<select>` 被隐藏，包装容器宽 **804.2px**、内层输入框 **804.2×42**；同一行「‹ 上一页」只有 69×**30**、跳页框 56×**30**，跳页组被挤到行末（仅剩 103px）。对照订阅页同类包装有约束：`[实测]` **108×42**。
- **问题**：这是弹窗里最显眼的布局塌陷 —— "10 条/页"被拉成一条长条，42px 与 30px 混排，跳页控件被压到边角。
- **建议**：`.doc-pager .searchable-select { width: 108px; flex: 0 0 auto }` + `.doc-pager .searchable-select-input { height: 30px; font-size: var(--fs-nano) }`（与同行控件同高）。
- **成本**：小

### A3 ★★ 分页栏内四种控件高度：42 / 40 / 36 / 32
- **位置**：`publish/subscription.html:496-507`；`publish/theme.css:1105`（上下页 36）、`:1108-1110`（跳页框 32）、`:1720-1730`（每页条数兜底写的是 32，**但原生 select 已被隐藏，是死代码**）、`:352-355`（包装后输入框 = `--control-h-md` 42）
- **现状**：`[实测]` 每页条数 42、页码 40、上下页 36、跳页框 32。另：`theme.css:1107` 注释写着「跳页输入框：与分页按钮同高」，而按钮已是 36、输入框仍 32 —— **本次分页栏改动把这条注释变成过期信息，建议一并修正**。
- **问题**：刚统一过视觉的一栏里四种高度并存，"统一感"打折；注释与值矛盾会误导后续维护。
- **建议**：以 36px 为这一栏唯一基准：补 `.pagination .searchable-select-input { height: 36px; font-size: var(--fs-xs) }`，把 `.pagination input` 高度改 36，删除或改写 `.page-size-select` 兜底块。
- **成本**：小

### A4 ★★ 「共 N 条」在三个页面位置与字号不一致
- **位置**：`publish/index.html:183-188`（`.result-count { margin-right: auto; font-size: var(--fs-sm) }`）、`publish/subscription.html:12`（`--fs-xs`）、`publish/task.html:12`（`--fs-xs`）
- **现状**：`[源码]` 首页靠 `margin-right: auto` 把计数推到最左，订阅页/task 页靠 `.card-head` 的 `space-between` 整体靠右；字号 `fs-sm` vs `fs-xs` 两种。
- **问题**：同一语义信息在三页之间左/右横跳、字号还不同，切换页面时眼睛要重新找。
- **建议**：统一「卡片头左端 = 共 N 条、右端 = 操作按钮」，在 `theme.css` 的 `.card-head` 段落加 `.card-head .result-count { margin-right: auto; font-size: var(--fs-xs) }`。
- **成本**：小

### A5 ★★★ 首页分页条没有页码、没有跳页、没有每页条数
- **位置**：`publish/index.html:520-524`（只有 `#btnPrev / #pageInfo / #btnNext`）、`js/page/index.js:428-443`；对照 `subscription.html:496-507` 与 `task.html:407-414`
- **现状**：`[源码]` 首页每页固定 10 条（`index.js:50`），翻到第 50 页要点 49 次「下一页」。
- **问题**：三页里只有入口页没有直达能力，用户会觉得"首页最不好用"。
- **建议**：最小改动 = 抄 task 页那套（`‹‹ 首页 / 末页 ››` + 跳页框，样式复用 `theme.css:1108`）；进一步可复用 `SubscriptionModel.buildPageNumbers`（`subscription-model.js:185-196`）渲染同款页码条。
- **成本**：中

### A6 ★★ task 页跳页框是"裸输入框"，三页跳页控件三种尺寸
- **位置**：`publish/task.html:413`、`subscription.html:506`（有「前往 … 页」文案）、`index.html:825-827`（有「跳至 … 页」）
- **现状**：`[实测]` 文档弹窗版 56×30；`[源码]` 分页栏版 72×32；task 版独一份没有文案，只能靠 `title` 悬停。
- **问题**：用户看到一个孤零零的数字框，不知道干什么用；且比同行按钮矮 4px。
- **建议**：task 页包一层 `<span class="page-jump">跳至 <input> 页</span>`；三处统一为 36px 高、文案统一「跳至 N 页」。
- **成本**：小

### A7 ★ 窄屏下分页条不换行（**实测后降级**）
- **位置**：`publish/theme.css:1094-1103`（无 `flex-wrap`，默认 nowrap）、`:1732-1740`
- **现状**：`[实测]` **900px 视口**：分页条内容 805 > 容器 803，**仅溢出 2px**，页面**没有**出现横向滚动条，跳页控件仍在视口内（`in-viewport`）；**1024px 视口**：无溢出。
- **问题**：原判断「跳页控件被推到屏幕外、整页横向滚动」**不成立**。真实影响仅为极窄视口下 2px 级挤压。
- **建议**：低优先。若要防极端情况，给 `.pagination { flex-wrap: wrap; row-gap: var(--sp1) }` 即可，不必做媒体查询。
- **成本**：小

### A8 ★★ 翻页后纵向滚动位置不重置
- **位置**：`js/page/publish-view.js:196-202`、`js/page/subscription.js:388-404`、`js/page/task.js:249-294`；`index.html:221-230`（`.tbl-scroll` 有 `max-height: clamp(320px,68vh,820px)` + `overflow:auto`）
- **现状**：`[源码]` 全 `js/page` 目录 **grep `scrollTop`/`scrollIntoView` 零命中**。
- **问题**：在表格里往下滚了半屏再点「下一页」，新页直接停在中下部，前几行看不到。横向滚动位置保留是对的，纵向需要重置。
