## proxy.js 增加「本地录制 + 离线回放」（外网也能调内网接口）

需求：后端在公司内网，到外网无法响应，希望把真实响应存本地用于模拟。

实现（只改 `proxy.js`，**前端零改动**）：
- 新增记忆化缓存目录 `cache/`（默认 `./cache`，`PROXY_CACHE_DIR` 可改），
  文件 `cache/<sha1>.json` + `cache/_index.json` 索引。
- **缓存 key 规则**：`sha1(method | pathname | 查询参数(剔除 n) | 规范化 JSON 请求体)`。
  - **必须剔除 `?n=` 防缓存随机数**，否则每个请求都是新条目、永远命中不了；
  - 请求体参与 key（JSON 键递归排序规范化），所以 `getPublishDataList` 不同 `pageNum` 各自成条目；
  - `token` 不参与 key。
- **只录 HTTP 200**：token 只有 12h 有效期，若把 401/500 录进去，离线回放拿到的就是错误。
- **自动回退**：默认先真实转发，`proxyReq.on('error')` 时（ENOTFOUND 等）回退读缓存，
  回放响应带 `X-Served-From: cache` / `X-Cache-Recorded-At`。
- 请求体必须先缓冲（`req.on('data')` 收集）才能参与 key，故不再 `req.pipe(proxyReq)`，改 `proxyReq.write(bodyBuf)`；
  响应同理要先收集 chunks 才能写缓存，不再直接 `proxyRes.pipe(res)`。
- 环境变量：`PROXY_OFFLINE=1` 纯离线（完全不发网络请求，未命中返回 404 提示补录）、
  `PROXY_RECORD=0` 关录制。
- 管理端点：`GET /cache/list`、`GET /cache/clear`；`/health` 增加 offline/record/cacheDir/cacheCount。

验证（无头，桩后端 + 真实起代理子进程，共 23 条断言全过）：
- 离线回放、CORS 头、不同 n 命中同一条、未命中 404 提示、请求体参与 key、JSON 键序无关；
- **端到端**：在线录制 → 换 n 缓存不膨胀 → 500 不录制 → 掐掉桩后端 → **自动回退缓存（X-Served-From: cache）**；
- 真实启动冒烟：新代理 `/health` 返回 offline/record/cacheDir/cacheCount，`/cache/list` 正常。

⚠️ **踩坑：端口 3000 上一直跑着旧版代理**（之前会话启动的进程没重启）。
冒烟时 `/health` 返回旧格式（无 offline/cacheCount）、`/cache/list` 被旧代理当普通请求转发到内网
→ `getaddrinfo ENOTFOUND`。**改完 proxy.js 必须重启代理进程才生效**，用 3011 端口验证通过。

文档：README 补「离线回放」章节（用法 + 缓存 key 规则表 + 两个 ⚠️）、项目结构加 `cache/`、
配置说明改为环境变量表、故障排除加「问题 4：本地缓存中没有这条记录」。
