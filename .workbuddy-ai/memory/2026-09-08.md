## 按 待修改.md 修正订阅链路（service-api.js / subscribe-dialog.js）

### 1. buildSubscribeBody 字段构造（第 1 步，此前已部分落地）
- `prodSysServeNoList` 原逻辑把 `serverCoding`（如 `ObsOpenAccountGetRedirectUrl`）去字母后拼 `callerComponent`，结果是 `["E00406TO"]`。
- 正确规律（HAR 抓包）：`prodSysServeNoList[0]` = `callerComponent` + `sysServeNo` 尾部的 `TO\d+`，
  即 `E00301TO1197` + `E00406` → `E00406TO1197`。
- 同时从 row/form 回填 id / publishId / serviceId / assemblyNo / deptId 等 20+ 字段；
  并区分「提供者编号」(sysServeNo/serviceNumber/targetServeNo) 与「接口编码」(interfaceCode/sysEnName/sysServeEnName)。
- 去掉了重复的 `if (form) { serviceName... }` 块（后面统一覆盖）。

### 2. subscribeWithForm 参数语义
- 形参 `serverCoding` → `rowOrCode`，订阅弹窗必须传**整个 row**，否则 buildSubscribeBody 拿不到 sysServeNo。

### 3. 文档列表接口字段（HAR 响应核对）
- `POST /itamp-tool/intfcMgmt/docList` 响应是 `{ code:'200', data:{ total, rows:[...] } }`，
  **数组字段是 `rows`（不是 records/list），记录 ID 是 `value`（不是 docInstId）**。
- 已改：`fetchDocList` 解析链加 `json?.data?.rows`；`renderDocTable` / `toggleDocAll` / `syncDocAllState` /
  `confirmDocSelection` 的 ID 取值统一为 `d.value || d.docInstId || d.id`。
  （syncDocAllState 待修改.md 里没点名，但用 d.id 会导致全选态不联动，一并修了。）
