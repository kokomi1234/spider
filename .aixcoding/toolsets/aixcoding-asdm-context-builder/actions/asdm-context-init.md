# 上下文初始化指令（asdm-context-init）

## 目的

引导 AI 为当前工作区扫描实际代码结构，基于 Spec 模板生成 `.aixcoding/contexts/index.md`。

## 语言检测

在生成前检测环境语言（中文/英文），所有输出统一使用该语言。

## 步骤 0 — 前置检查（目标文件存在性扫描）

**在执行任何生成操作之前，必须先扫描 `.aixcoding/contexts/` 目录**，确定目标文件是否已存在。

### 0.1 扫描目录

列出 `.aixcoding/contexts/` 及其子目录（如 `layer-2/`）中的所有文件，记录每个文件的名称和最后修改时间。

### 0.2 判断文件状态

对扫描到的每个文件，判断其与当前项目的**一致性状态**：

| 状态 | 条件 | 处理方式 |
|------|------|----------|
| 🟢 一致 | 内容与当前项目结构匹配 | 跳过生成，告知用户无需更新 |
| 🟡 过时 | 文件存在但内容与当前项目不一致 | 提示用户差异点，询问是否覆盖/合并更新 |
| 🔴 缺失 | 目标位置无此文件 | 标记为待生成 |

**一致性判断方法**（快速启发式，不需要逐行对比）：
1. `index.md`：检查目录树中的顶层目录名是否与 `list_dir` 结果匹配
2. L2 文件：检查文件中引用的关键路径/类名/端点是否仍存在于项目中

### 0.3 输出检查报告并向用户确认

将检查结果以表格形式呈现给用户：

```markdown
## 前置检查报告

| 目标文件 | 状态 | 说明 | 操作建议 |
|----------|------|------|----------|
| index.md | 🟢 一致 / 🟡 过时 / 🔴 缺失 | {具体说明} | 保留 / 覆盖 / 新建 |
| layer-2/architecture.md | ... | ... | ... |
| layer-2/standard-project-structure.md | 🔴 缺失 | 尚未生成 | 新建 |
| ... | ... | ... | ... |
```

**关键约束**：
- 若任何文件处于 🟢 状态，必须明确告知用户该文件将被**跳过**而非覆写
- 若存在 🟡 状态文件，**必须暂停等待用户确认**后再继续（除非用户在初始请求中明确要求全量覆盖）
- 仅对 🔴 缺失文件或用户确认为 🟡 覆写的文件执行后续生成步骤

## 执行步骤

### 1. 初始化目录

创建 `.aixcoding/contexts/` 和 `.aixcoding/contexts/layer-2/` 目录（如不存在）。

### 2. 生成 index.md（仅此一个文件）

**仅生成 `index.md`** 到 `.aixcoding/contexts/`。以 `specs/layer-1/index.md` 为模板，将 `[占位符]` 替换为工作区真实信息。

**内容原则 — 精简务实**：

| 允许 | 禁止 |
|------|------|
| 项目名称、描述（≤3 句话） | "L1/L2 层级职责边界"等框架性说明 |
| 技术栈一行清单 | Mermaid 图表 |
| 实际目录树（≤15 行） | 大量空白占位符（`[创建日期]` 等） |
| L2 文件导航表 | 代码块示例、命令示例 |
| 版本历史一行记录 | AI 使用指南、常见任务指引 |

关键约束：
- 目录树必须反映**当前项目的真实结构**，而非通用模板
- 不写"如何使用此上下文"、"问题排查"等泛用性指导段落
- 总行数控制在 **80 行以内**

### 3. 按需生成 L2 层

index.md 审查通过后，用户可请求逐一生成以下 L2 文件（每个单独请求）：

| 文件名 | 说明 |
|--------|------|
| `standard-project-structure.md` | 项目结构详情 |
| `standard-coding-style.md` | 编码规范 |
| `data-models.md` | 数据模型 |
| `deployment.md` | 部署配置 |
| `api.md` | API 文档 |
| `architecture.md` | 架构设计 |

## 工作区分析要点

生成前扫描以下信息用于填充模板：
- 技术栈和框架（从 package.json / pom.xml / go.mod 等读取）
- 项目顶层目录结构（list_dir）
- 关键源码位置（Java 包结构、Vue pages/components 等）
- 业务领域（从 README 或代码注释推断）

## 输出质量保证

生成后执行 Markdown 语法验证和质量检查：

1. **加载 Skill 规范**：读取 `.aixcoding/skills/markdownlint/SKILL.md`，遵循其中定义的工作流、规则和配置进行验证
2. **验证范围**：对 `.aixcoding/contexts/` 下所有新生成的 `.md` 文件执行 lint 检查
3. **处理结果**：
   - ✅ Exit code 0 → 通过
   - ⚠️ 发现问题 → 能自动修复的执行 `--fix`，需人工判断的向用户报告
