# Test Plan 文档规范

## 概述

此规范定义功能测试计划（Test Plan）文档的结构模板，供 `asdm-harness-testplan` action 基于 PRD 文档生成功能测试计划时参照。本规范**聚焦于功能测试**——验证系统行为是否符合 PRD 定义的功能需求。文档以测试套件（Phase）组织测试用例（Task），每个用例包含明确的测试步骤。

## 文档命名

```text
FT-{id}-{name}-TestPlan.md
```

存放路径：`.asdm/workspace/asdm-harness/feat/FT-{id}-{name}/`

## 测试套件（Phase）划分原则

| 原则 | 说明 |
| ------ | ------ |
| 场景覆盖 | 每个套件对应 PRD 中的一个使用场景或功能模块 |
| 独立可测 | 套件之间保持独立，减少交叉依赖 |
| 优先级排序 | 核心流程 → 辅助功能 → 边界异常 |

## 测试用例（Task）编写规范

### 用例编号

格式：`{Suite}.{Case}` 如 `1.1`、`2.3`

### 测试类型

| 类型 | 适用场景 | 典型特征 |
|------|----------|----------|
| 功能测试 | 验证功能正确性 | 给定输入 → 验证输出是否符合预期 |
| 边界测试 | 验证边界条件 | 极值、空值、超长输入 |
| 异常测试 | 验证异常处理 | 无效输入、缺失参数、未授权访问 |

### 测试步骤格式

每个测试步骤使用统一格式：

| 步骤 | 操作 | 预期结果 |
| :----: | ------ | ------ |

- **步骤编号**：从 1 开始递增
- **操作**：具体的执行动作，可使用 curl 命令、UI 操作描述、API 调用等
- **预期结果**：明确的可验证结果，包括 HTTP 状态码、响应字段、数据库状态等

### 测试数据规范

- 测试数据应与预期结果对应
- 区分正常数据和异常数据
- 标注数据的特殊含义（如边界值、无效值）

## 测试执行与统计

### 状态标记

| 状态 | 图标 | 含义 |
|------|:----:|------|
| 未执行 | ❌ | 尚未执行 |
| 执行中 | ⏳ | 正在执行 |
| 通过 | ✅ | 所有步骤通过 |
| 失败 | ❎ | 步骤未通过 |
| 阻塞 | 🚫 | 因环境/依赖问题无法执行 |
