# Overall Plan 模板规范

## 概述

此规范定义了项目总体计划文档（`overall-plan.md`）的结构模板，供 `asdm-harness-init` action 生成初始计划时参照。模板面向 AIM（AI-First System Development Methodology）开发流程，覆盖项目概述、产品规划范围、核心概念、分支策略、迭代信息和特性清单。

## 模板结构

```markdown
# <项目名称> 总体计划

> 本文档梳理 <项目名称> 项目的完整业务场景，涵盖系统概述、功能模块、业务逻辑和特性列表。
>
> 最后更新：YYYY-MM-DD

---

## 核心概念：模块与特性

本文档使用**模块**和**特性**两个核心概念来组织项目规划：

| 维度 | 模块（Module） | 特性（Feature） |
|------|----------------|-----------------|
| **定义** | 项目中的功能区域，从业务领域角度进行稳定划分 | 项目研发过程中规划的可交付单元 |
| **稳定性** | 相对稳定，反映业务领域边界 | 持续变化，随研发迭代演进 |
| **生命周期** | 长期存在 | 规划 → 实现 → 交付 → 维护 |
| **关系** | 特性对模块产生变更作用 | 每个特性归属一个或多个模块 |

- 主分支：`main`
- 功能分支：`feat/<author>/<feature-name>`
- 发布分支：`releases/release-<version>`
- 修复分支：`hotfix/<issue-id>`

---

## 团队协作流程

1. 需求澄清 → 执行 `/asdm-harness-askme` 消除歧义
2. 产品设计 → 执行 `/asdm-harness-design` 输出 PRD
3. 任务规划 → 执行 `/asdm-harness-plan` 输出开发计划
4. 编码实现 → 执行 `/asdm-harness-develop` 自动编码闭环
5. 测试验证 → 执行 `/asdm-harness-testplan` 生成测试计划并验证
6. 验收审查 → 执行 `/asdm-harness-verify` 生成功能验收报告
7. 构建发布 → 执行 `/asdm-harness-deploy`（后续实现）
```

## 填充规则

Action 生成 `overall-plan.md` 时应遵循以下规则：

1. **项目信息自动采集**：从 `.asdm/contexts/index.md` 和服务端 `README.md` 读取项目名称、定位、技术栈、代码库信息
2. **模块列表从上下文推断**：根据项目实际架构（微服务/模块）生成功能模块清单，而非硬编码
3. **特性列表初始为空**：首次生成时特性清单应为空或仅包含模板占位，等待实际需求录入
4. **日期自动填充**：所有日期字段填入当前日期
5. **迭代信息按默认值**：首次生成迭代版本设为 `v0.0.1`，后续由 `/asdm-harness-plan` 更新
6. **不要照搬参考文档的具体数据**：参考文档中的特性编号、人员、日期等为 ASDM 项目特有，生成时必须替换为当前项目实际信息
