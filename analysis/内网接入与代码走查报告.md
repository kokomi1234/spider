## 一、业务逻辑与调用链路

### 1.1 整体链路

```
浏览器页面 (index.html / task.html / subscription.html)
   │
   ├─► js/core/runtime-config.js   注入 window.__APP_CONFIG__（apiBase、endpoints）
   │
   ├─► js/core/api-client.js:33    API.call(path, {method, body, query, signal})
   │     └─ BASE_URL = location.origin   （runtime-config.js:21）
   │
   ├─► js/api/*.js                 5 个领域模块，各自 isEnabled() 门禁 + request() 封装
   │     service-api / tool-api / task-api / sys-api / user-api
   │
   └─► js/page/*.js + js/ui/*.js   页面状态、渲染、前端兜底过滤、订阅弹窗
         │
         ▼
   fetch('http://localhost:3000/itamp-xxx/...')    ← 开发环境
         │
         ▼
   publish/proxy.js:359
         ├─ 静态文件（GET + 有扩展名）→ 直接读盘，Cache-Control: max-age=86400
         ├─ /health、/cache/list、/cache/clear → 管理端点
         └─ 其他 → 转发到 TARGET(http://itamp.bocsys.cn) + path
                    注入 token，成功(200)自动录制到 cache/，失败回退缓存
```

### 1.2 三条业务线

| 页面 | 主接口 | 特征 |
|---|---|---|
| `index.html` 服务发布数据查询 | `getPublishDataList` | 全量拉取（pageSize 200，最多 200/页）+ 前端兜底过滤 + 客户端排序 + 订阅 |
| `task.html` 任务单查询 | `taskFormSelectList` | 后端分页 + 5 个字典接口 + 评委/部门选择 |
| `subscription.html` 订阅关系查询 | `getSubscriptionPublishHistoryList` | 后端分页 + 投产优先级排序 + 逾期标红 |

### 1.3 接口配置门禁（关键设计）

5 个 api 模块都有 `isEnabled(key)` 门禁：`window.__APP_CONFIG__` 里对应 endpoint 为空时，
**不发请求，直接返回 `{ok:true, local:true}`**。默认 `runtime-config.js:35-36` 的
`endpoints` 是空对象 —— 意味着**开箱即用时所有写操作都是"本地假成功"**。

这个设计让前端可以脱离后端开发，但上线时一旦漏配，会表现为"操作成功但后端无数据"。

## 四、内网环境需要额外配置/调整的关键项

按上线前必须完成的顺序：

1. **网络**：确认 `itamp.bocsys.cn` 在内网可达（当前 NXDOMAIN）。若走 https，`proxy.js` 需改用 https 模块（A5）。
2. **Token**：`.env` 的 `PROXY_TOKEN` 必须存在且有效（约 12h 过期）—— 缺失会触发 A1 挂死。
3. **补齐公共请求头**：`systemId: itamp`、`ssopSessionId`、`authMethods: udp`（A3）。**这是最可能卡住接入的一项**，当前代理只发 token。
4. **给代理加超时**（A2），否则网络异常时全站挂起。
5. **配置 `window.__APP_CONFIG__.endpoints` / `endpointMethods`**：不配则订阅类接口全程"假成功"（B3）。
6. **上线前必须删除 service-api.js 的硬编码样例数据**（B1）并**重写 unsubscribe 请求体**（B2）——否则会污染生产数据。
7. **录制剩余 23 个接口的缓存**（2.4），否则离线/演示环境大面积 404。
8. 开发环境把静态文件缓存改成 `no-store`（A7），避免"改了没生效"的误判。
